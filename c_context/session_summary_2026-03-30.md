## Key Design Decisions

### 1. Using git mv for Renames
**Decision:** Use `git mv` instead of manual rename + git add
**Rationale:**
- Preserves file history through rename
- Enables git blame/log to follow files across directory changes
- Critical for reproducibility and citation tracking

### 2. Bulk Updates via sed
**Decision:** Use sed pattern replacement for similar R scripts
**Rationale:**
- 12 cleaning scripts with identical pattern replacements
- Reduces human error vs. manual editing
- Ensures consistency across all files
- Faster execution (single command vs. 24 edits)

**Alternative Considered:** Manual Edit tool calls
**Rejected Because:** Higher error risk, more time-consuming

### 3. Comprehensive Testing Before Commit
**Decision:** Test R pipeline, Python scripts, and git patterns before committing
**Rationale:**
- Early detection of broken references
- Validates path resolution across all systems
- Ensures functional pipeline after restructure
- Reduces risk of broken state in git history

### 4. Atomic Commit Strategy
**Decision:** Stage all changes before single commit
**Rationale:**
- Ensures repository never in inconsistent state
- Simplifies rollback if issues discovered
- Clear history: one commit = one logical change
- Easier for collaborators to review and understand
